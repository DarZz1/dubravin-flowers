# Изменения в CMS и серверной логике (обновление dubravin-flowers-fixed)

Дата: 2026-10-15

## Главное: изменения теперь сохраняются НА СЕРВЕРЕ, а не в браузере

Все правки в панели `/admin` (товары, подборки, hero, фото, пароли) уходят на
сервер хостинга и **сразу публикуются для всех посетителей** — ничего
скачивать/загружать вручную не нужно:

- Панель при старте опрашивает серверный API (`/api/health`). Если сервер CMS
  работает — это единственный источник данных: чтение (`GET /api/content`),
  сохранение (`PUT /api/admin/content` с защитой от перезаписи чужих правок
  через `If-Match`), загрузка фото отдельными файлами (multipart →
  `POST /api/admin/products/<id>/photos`).
- В серверном режиме панель **больше не пишет данные в localStorage** браузера
  (раньше локальная копия могла «перебивать» серверную картину).
- Витрина сайта читает каталог с сервера при каждой загрузке страницы —
  посетители видят правки немедленно.
- Если сервера CMS нет (например, открытие файлов с диска), панель честно
  предупреждает об этом во вкладке «Данные» и работает локально — как резерв.

### Критическая причина, почему раньше правки оставались в браузере

Файл `_redirects` обрабатывается Netlify **раньше** `netlify.toml`, и правило
`/* → /:splat.html` перехватывало все запросы `/api/*` и `/img/*` — функции
сервера CMS просто не вызывались, панель не находила сервер и падала в
локальный режим localStorage. В `_redirects` добавлены правила:

```
/api/*    /.netlify/functions/api/:splat    200!
/img/*    /.netlify/functions/img/:splat    200!
```

## Изменения в панели управления (по пунктам ТЗ)

1. **Убран текст** «Изменения сохраняются в этом браузере сразу… скачайте
   data.json и загрузите его в корень сайта» из шапки панели (и устаревшая
   подпись в подвале страницы входа).
2. **Вкладка «Данные»**: устаревший блок про localStorage-черновики и ручную
   публикацию data.json удалён. Вместо него — статус: в серверном режиме
   «изменения сохраняются на сервере и сразу публикуются», кнопки
   Скачать/Импортировать/Сбросить остались как инструмент резервного
   копирования и переноса. Смена пароля в серверном режиме уходит на сервер
   (`POST /api/admin/password`) и действует для всех устройств.
3. **Серверное хранение** — см. выше.
4. **Вкладка «Товары»**: кнопка «+ Добавить товар» перенесена наверх, в шапку
   карточки (справа от счётчика товаров) — листать список до конца не нужно.
5. **Карточка товара**: поле «ID (номер папки с фото)» убрано; номер
   присваивается автоматически при сохранении нового товара (следующий
   свободный: 62, 63, …).
6. **Подборки**: у каждой подборки появился чекбокс «🏠 На главной». На главной
   странице сайта показываются **только** отмеченные подборки и **не более 4**.
   Когда 4 слота заняты, остальные чекбоксы блокируются (с подсказкой), пока не
   освободится место. Страховка лимита есть и в данных (клиент + сервер), и в
   шаблоне главной.
7. **Карточка товара**: чекбокс «Акция» убран. Логика автоматическая: заполнена
   «Старая цена» (и она выше текущей) → товар получает плашку «Акция» и
   автоматически добавляется в подборку «Акции» (подборка создаётся сама при
   первом акционном товаре; в списке подборок она помечена «(авто)» и
   заблокирована для ручного включения). Старую цену убрали → плашка и
   принадлежность к «Акциям» снимаются при сохранении. Правило продублировано
   на сервере (`sale = old > price`).
8. **Карточка товара**: чекбокс «Показывать на главной» разрешает отметить не
   более 4 товаров — попытка отметить 5-й блокируется с подсказкой. Витрина
   дополнительно режет блок «Хиты этой недели» до 4 карточек.
9. **Карточка товара, «Состав»**: максимум 10 позиций. На 10-й кнопка
   «+ Позиция состава» блокируется и меняет подпись; после удаления одной
   позиции снова активна. Лимит закреплён в санитизации данных (клиент и
   сервер).
10. **Обложка-заглушка**: из исходных данных убраны «нарисованные» обложки
    (раньше заглушки хранились прямо в imgs/cover и не пропадали после загрузки
    настоящих фото). Теперь заглушка — только визуальный фолбэк при выводе:
    нет фото → показывается фирменный плэйсхолдер; добавили фото → он исчезает.
11. **Карточка товара, изображения**: лимит **5 фото** — на лимите кнопка
    загрузки блокируется с подсказкой. Поле «путь/ссылка» и кнопка «Добавить
    путь» убраны: файлы выбираются с устройства и **автоматически загружаются
    на сервер** (оригиналы, multipart; сервер проверяет сигнатуру файла,
    сохраняет в Netlify Blobs / на диск и возвращает готовые URL `img/<id>/<n>.jpg`).

## Изменения в бэкенде

- `backend/server/sanitize.js` — у подборок появилось поле `main`; лимиты:
  5 фото на товар, 10 позиций состава, не более 4 «главных» товаров и подборок
  (серверная страховка правил CMS).
- `backend/server/config.js` — `maxPhotosPerProduct: 5`, новые лимиты.
- `backend/server/content.js` — дозагрузка фото продолжает нумерацию файлов по
  данным БД (раньше на Netlify новые фото могли затереть существующие);
  превышение лимита фото → `409 photo-limit`; создание товара возвращает `id`.
- `backend/server/api.js` — `GET /api/auth/me` возвращает токен: панель
  восстанавливает вход после перезагрузки вкладки по httpOnly-куке
  (раньше каждая перезагрузка требовала повторного входа).
- `backend/server/store.js` — публикация `data.json` отключена в окружении
  Netlify (корень только для чтения; витрина читает `GET /api/content`).
- `backend/netlify/api.mjs` — поиск файлов `backend/server/*` по нескольким
  раскладкам каталогов (локально и в бандле функции Netlify).
- `netlify.toml` — в бандл функции включаются `node_modules/busboy` и
  `node_modules/streamsearch` (требуются в рантайме; `@netlify/blobs`
  предоставляет сам рантайм Functions).
- **Восстановлены отсутствовавшие CLI** (без них было невозможно создать админа
  для Netlify):
  - `backend/cli/admin.js` — `bootstrap` (печатает переменные окружения
    DF_BOOTSTRAP_LOGIN/DF_BOOTSTRAP_HASH/DF_SECRET…), `create` (учётка в
    локальной БД для VPS), `hash`;
  - `backend/cli/seed.js` — пересборка `backend/seed.json` из витринных
    модулей (`npm run backend:seed`).
- `backend/seed.json` — пересобран: без заглушек, с флагами «На главной»
  (4 подборки) и подборкой «Акции».

## Сессия админа (исправленные баги)

- Раньше через 30 секунд после входа через сервер панель «выбрасывала» на экран
  входа (таймер бездействия проверял только локальную сессию). Теперь серверная
  сессия поддерживается скользящим пингом, а при её истечении панель корректно
  просит войти заново.
- Активность в панели продлевает серверную сессию (30 мин скользящего
  таймаута), перезагрузка вкладки не требует повторного входа, пока жива кука.

## Экономия лимитов Netlify free

В серверном режиме витрина больше не «пробует наугад» файлы
`img/<id>/<n>.<ext>` для товаров без фото (это были десятки запросов к функции
на каждой странице). Нет фото в БД → сразу фирменная заглушка, 0 запросов.
Папка `img/` по-прежнему работает на статическом хостинге без сервера.

# Деплой на Netlify (превью) — ОБЯЗАТЕЛЬНО через Git-импорт

> ⚠️ **Netlify Drop (перетаскивание zip) не подходит**: он не запускает сборку,
> функции не получат зависимости и серверная CMS не заработает (сайт откроется,
> но панель уйдёт в локальный режим). Нужен импорт репозитория или
> `netlify deploy --build` через CLI.

1. Загрузите содержимое этой сборки в репозиторий GitHub
   (например, в существующий `DarZz1/dubravin-flowers`).
2. Netlify → **Add new site → Import an existing project** → выберите репозиторий.
   Настройки сборки подхватятся из `netlify.toml`:
   - Build command: `npm install --omit=dev --no-audit --no-fund`
   - Publish directory: `.`
   - Functions directory: `backend/netlify`
3. **Создайте админа** (локально, нужен Node.js 20+):

   ```bash
   node backend/cli/admin.js bootstrap --login <ваш-логин> --random 16
   ```

   Команда напечатает 5 переменных и одноразовый пароль:

   ```
   DF_BOOTSTRAP_LOGIN=…
   DF_BOOTSTRAP_HASH=scrypt$…      ← хэш, а не пароль
   DF_SECRET=…
   NODE_ENV=production
   DF_TRUST_PROXY=1
   ```

4. Скопируйте все пять переменных в **Site configuration → Environment
   variables**, затем **Deployments → Trigger deploy → Deploy site**.
   При первом запросе функция создаст учётку из этих переменных.
5. Проверьте:

   ```bash
   curl -s https://<ваш-сайт>.netlify.app/api/health
   # ожидаем: {"ok":true,…,"storage":"netlify-blobs","cms":"server"}
   ```

   Откройте `/admin` → войдите логином и паролем из шага 3 → правки сразу видны
   на сайте всем посетителям.
6. После успешного входа переменные `DF_BOOTSTRAP_*` из Netlify лучше удалить.

Данные (товары, фото, админы, сессии) хранятся в **Netlify Blobs** — они
переживают деплои и заморозку инстансов; на бесплатном тарифе этого достаточно.

# Перенос на Beget (позже)

- **Вариант A (полная копия Netlify-поведения): VPS / Node.js-хостинг Beget.**
  Запускаете `node backend/server/server.js` (те же API, авторизация и медиа,
  но данные — в файлах `backend/data/`), nginx проксирует `/api/*` и `/img/*`
  на него, статику отдаёт как обычно. Админ создаётся командой
  `node backend/cli/admin.js create --login <логин>`. Перенос данных:
  «Данные → Скачать data.json» на Netlify → «Импортировать data.json» на новой
  панели (или `PUT /api/admin/content`). Фото — экспортом из Netlify Blobs /
  повторной загрузкой.
- **Вариант B: обычный shared-хостинг Beget (только статика).** Серверной CMS
  там нет — панель сама определит это и предупредит во вкладке «Данные»;
  правки будут локальными, публикация через data.json. Для сценария
  «изменения сразу для всех посетителей» нужен вариант A.

# Локальная проверка (как на хостинге)

```bash
node backend/cli/admin.js create --login admin --password <пароль>
npm run server        # http://127.0.0.1:8090/  и  /admin
```
