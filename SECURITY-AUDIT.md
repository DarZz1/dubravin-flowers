## A01 · Broken Access Control

**Что сделано**

- Все `/api/admin/*` требуют валидную сессию; без неё — `401`, без утечки
  деталей. Проверено перебором **23 маршрутов** (`A01: каждый защищённый
  маршрут без сессии → 401`).
- Изменения требуют подтверждения происхождения запроса: `Authorization: Bearer`,
  `X-CSRF-Token` (double-submit) — иначе `403 csrf`.
- Служебные пути не отдаются по HTTP: `backend/`, `tests/`, `deploy/`,
  `tools/`, `package*.json`, `netlify.toml`, `vercel.json`, `_headers`,
  `_redirects`, `.htaccess`, `.env`, `.git/*` → 404/403. Проверено 19 URL.
- Path traversal закрыт на двух уровнях: нормализация пути **до** проверок и
  сравнение с корнем; отдельно — нормализация `id` товара и разрешение пути
  внутри каталога медиа (`mediaResolve`, `safeSubdir`).
- Методы ограничены по каждому маршруту (`405`, а не `404`/`200`), включая
  динамические пути.

**Проверки**

```
A01: каждый защищённый маршрут без сессии → 401           (23 маршрута)
A01: поддельный/мусорный токен не принимается             (8 вариантов токена)
A01: токен другой сессии не даёт доступ (HMAC от секрета)
A01: служебные файлы сервера не отдаются по HTTP          (19 URL)
A03: path traversal в URL не выводит за корень сайта      (10 векторов)
A03: traversal в id товара и подборки отклоняется         (10 векторов)
```

## A02 · Cryptographic Failures

**Что сделано**

- Пароль: `scrypt` N=2¹⁷ (131072), r=8, p=1, ключ 64 байта, соль 16 байт из CSPRNG.
  Формат `scrypt$N$r$p$salt$hash` — параметры хранятся вместе с хэшем, поэтому
  стоимость можно поднять позже без сброса паролей.
- Сравнение через `crypto.timingSafeEqual`. Для несуществующей учётки хэш
  всё равно считается (константа `DUMMY_HASH`) — время ответа не раскрывает
  наличие логина.
- Сессия: 32 байта CSPRNG (`randomBytes().toString("base64url")`). В БД —
  только `HMAC-SHA256(secret, token)`, поэтому утечка `db.json` не даёт доступа.
- Токен восстановления: одноразовый, 15 минут, в БД тоже только хэш.
- Кука: `HttpOnly`, `Secure` (на HTTPS), `SameSite=Strict`, `Path=/`,
  имя `__Host-df-session` на HTTPS (браузер дополнительно требует Secure и
  запрещает Domain). В http-режиме — `df-session` без `Secure`.
- `DF_SECRET` обязателен в production: без него сервер **отказывается стартовать**
  (`assertProductionReady`). В разработке генерируется одноразовый, о чём
  печатается предупреждение.
- `Math.random` в криптографии не используется (проверяется статически).

**Проверки**

```
A02: пароль хранится как scrypt с уникальной солью
A02: одинаковые пароли дают разные хэши + мусорный хэш не принимается (7 вариантов)
A02: токены сессий криптографически случайны и не повторяются
A02: сессии в БД — только HMAC-хэш токена
login: в БД хранится только хэш scrypt, не пароль
A04: клиент не получает ничего, что позволило бы проверить пароль офлайн
```

Замер на стенде: `scrypt` N=2¹⁷ ≈ 100–250 мс на проверку — незаметно для
человека и дорого для перебора. Команда `node backend/cli/admin.js doctor`
печатает фактическое время и предупреждает, если оно вышло за коридор 50–1000 мс.

## A03 · Injection

SQL-инъекции невозможны по построению: базы с SQL-запросами нет, хранилище —
JSON-файл с белой сборкой полей. Проверено, что инъекционные последовательности
(`'; DROP TABLE…`, `" OR 1=1 --`, `{"$gt":""}`, `1; rm -rf /`, `` `id` ``,
`$(whoami)`) сохраняются как обычные строки и не ломают чтение.

**XSS.** Защита трёхслойная:

1. **Сервер**: белый список полей (`sanitizeProduct`/`sanitizeCollection`/`sanitizeHero`),
   лимиты длин, `safeUrl()` для всех URL, отсечение `__proto__`/`constructor`/`prototype`
   и в JSON-теле (`stripDangerousKeys`), и в полях multipart-формы.
2. **Клиент**: боевой `esc()` из `assets/js/store.js` экранирует всё, что
   попадает в HTML; inline-обработчиков в шаблонах нет (проверяется статически).
3. **CSP**: `script-src 'self'` без `'unsafe-inline'` на витрине и `script-src 'self'`
   в админке; для API — `default-src 'none'; frame-ancestors 'none'; base-uri 'none'`.

Тест рендерит карточку товара с payload `<img src=x onerror=…><script>alert(1)</script>`
боевым `cardHTML()` и проверяет DOM: исполняемых узлов нет, `onerror` в разметке нет,
в `src` нет `javascript:`.

**Path traversal.** Десять векторов, включая `..%2f`, `%252e%252e`, `\\..\\`,
`....//`, `/img/../../backend/data/db.json` — все дают 404, содержимое системных
файлов в ответе не появляется. Имена загружаемых файлов игнорируются: сервер
генерирует их сам (`img/<ID>/<номер>.<ext>`).

**Command injection** исключена: `child_process` в серверном коде не используется
(только в `tools/pack.js` при сборке архива, с фиксированными аргументами).

## A04 · Insecure Design

**Принципы, заложенные в дизайн**

- Ничего не доверяем клиенту: даже данные из собственной БД проходят
  санитизацию перед выдачей (защита от подмены файла и битых бэкапов).
- Ответы об ошибках обезличены: `invalid-credentials` вместо «нет такого логина».
- Смена пароля отзывает **все** сессии админа — украденный токен умирает вместе
  с ротацией пароля.
- Смена пароля требует подтверждения текущего (кроме флага `mustChangePassword`).
- Оптимистичная блокировка по ревизии контента: параллельные правки двух
  админов не затирают друг друга (`409 rev-conflict`).
- Все мутации БД идут через одну последовательную очередь — гонка
  «прочитал-изменил-записал» исключена.
- Запись атомарна: `tmp` → `fsync` → `rename` → `fsync` каталога.
- Удаление карточки удаляет её медиафайлы; замена фото удаляет предыдущие;
  есть отдельная операция очистки «осиротевших» файлов.

**Осознанные ограничения**

1. **Один сервер — одна точка записи.** Очередь мутаций внутрипроцессная.
   При запуске нескольких инстансов за балансировщиком нужен внешний lock
   (Redis/Postgres) или общий файловый lock. В `store.js` это единственное
   место, которое потребуется доработать.
2. **JSON-БД не предназначена для высокой нагрузки записи.** Для текущего
   объёма (десятки товаров, единицы правок в день) запас многократный.
3. **Лимит по IP** (`DF_RATE_MAX`, по умолчанию 30 за 10 минут) считается
   по адресу из `X-Forwarded-For` только при `DF_TRUST_PROXY=1`. Без доверия
   к прокси злоумышленник за общим NAT не различается — это осознанный
   компромисс в пользу невозможности подделки заголовка.
4. **Восстановление доступа требует доступа к серверу** (CLI или уже
   авторизованный админ). Почты и SMS нет: для статического сайта без
   бэкенд-провайдера это единственный честный вариант, зато канал
   восстановления нельзя перехватить по сети.

## A05 · Security Misconfiguration

- Заголовки на **всех** ответах API: `X-Content-Type-Options: nosniff`,
  `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`,
  `Permissions-Policy: geolocation=(), microphone=(), camera=(), payment=()`,
  `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; base-uri 'none'`,
  `Cross-Origin-Resource-Policy: same-origin`, `Cross-Origin-Opener-Policy: same-origin`,
  `Cache-Control: no-store`. HSTS добавляется только на HTTPS.
- CORS по умолчанию отсутствует; включается одной переменной и только для
  точного совпадения origin (нужен на период переезда, когда витрина и API
  на разных доменах).
- Статика: служебные каталоги блокируются, `.json`/`.md` отдаются с корректным
  MIME, `nosniff` на всех ответах, `/admin` → `301 /admin/` + `X-Robots-Tag: noindex`.
- Кэширование разведено: CSS/JS — `max-age=604800`, изображения — `2592000`,
  HTML — `no-cache`, `data.json` — `no-store`, API — `no-store` + ETag.
- Ошибки не раскрывают стектрейсы, пути, `ENOENT` и внутренние типы исключений.
- В production сервер отказывается стартовать без `DF_SECRET` и предупреждает
  про bind на loopback без явного разрешения.
- gzip включён для текстовых ресурсов (витрина: 150 КБ → 49 КБ, 32,9%).

## A06 · Vulnerable and Outdated Components

Зависимостей рантайма **одна**: `busboy@^1.6.0` (разбор multipart, без
собственных зависимостей кроме `streamsearch`). Всё остальное — встроенные
модули Node: `http`, `fs`, `path`, `crypto`, `zlib`, `url`.

Такой состав выбран сознательно: меньше поверхность для CVE и нет нативной
сборки, которая ломается при переезде на другой хостинг. `jsdom` остаётся
только в `devDependencies` (нужен для генерации `backend/seed.json` и для
тестов), в рантайме сервера не используется.

Контроль: `npm audit --omit=dev` перед деплоем; требование `engines.node >= 20`.

## A07 · Identification and Authentication Failures

- Блокировка перебора: 5 неудач → 30 с, удвоение за каждую следующую, потолок
  15 минут. Счётчик переживает перезапуск (хранится в БД). Во время блокировки
  даже верный пароль отклоняется (`423`).
- Отдельный лимит по IP: 30 попыток входа за 10 минут → `429`.
- Сессия: 30 минут, скользящий таймаут (продлевается по активности), токен в
  `sessionStorage`-эквиваленте — httpOnly-кука умирает вместе с браузером.
- Валидация учётных данных: логин 3–64 символа, алфавит `[A-Za-z0-9._@-]`;
  пароль 8–128 символов. Ошибки валидации не раскрывают существование учётки.
- Все учётки равноправны технически, но смена пароля и выпуск токена
  восстановления требуют уже авторизованной сессии.
- Журнал фиксирует `auth.ok`, `auth.fail`, `auth.locked`, `auth.rate-limited`,
  `auth.invalid-input`, `auth.password-changed`, `auth.password-reset`,
  `admin.password-change-denied` — без паролей, токенов и хэшей.

Замер времени ответа для существующего и несуществующего логина совпадает
(в обеих ветках считается scrypt) — тест проверяет разницу средних.

## A08 · Software and Data Integrity Failures

- Белая сборка объектов: из входящих данных берутся только известные поля,
  `__proto__`/`constructor`/`prototype` отбрасываются и в JSON, и в multipart-полях.
  Тест проверяет, что `Object.prototype` не загрязняется.
- Формат загружаемого изображения определяется по байтам (сигнатура) **и**
  проверяется структурно (маркеры конца файла). MIME и расширение из формы
  игнорируются: файл `shell.png` с содержимым `<?php … ?>` отклоняется,
  а PNG, названный `lying.jpg`, сохраняется как `1.png`.
- Белый список форматов: JPEG, PNG, WebP. Лимиты: 8 МБ на файл, 24 МБ на запрос,
  ≤8 фото на товар.
- `data.json` публикуется атомарно (tmp → rename), временных файлов не остаётся.
- Целостность проверяется операционно: `node backend/cli/admin.js doctor`
  сверяет ссылки в БД с фактическим содержимым `img/` и печатает
  «ссылки без файлов» и «файлы без ссылок».

## A09 · Security Logging and Monitoring Failures

- Журнал `backend/data/audit.log` в формате NDJSON: `{ts, event, data}`.
- Функция `scrub()` вымарывает всё, что похоже на секрет: поля, содержащие
  `pass`, `token`, `secret`, `hash`, `cookie`, `authorization`, заменяются на
  `[redacted]`. Тест проверяет, что ни пароль, ни токен, ни хэш в журнале
  не встречаются.
- Ротация при 5 МБ (`audit.log` → `audit.log.1`).
- Доступ к журналу через API — только авторизованному админу
  (`GET /api/admin/audit`, последние 300 записей); по HTTP файл не отдаётся.
- Журнал отказоустойчив: ошибка записи не роняет запрос.
- Процессы `uncaughtException` и `unhandledRejection` логируются, сервер
  завершается плавно по SIGTERM/SIGINT (не рвёт активные запросы).

## A10 · Server-Side Request Forgery

Исходящих HTTP-запросов сервер не делает вовсе: нет ни `fetch`, ни `http.request`
в серверном коде. Единственные URL во входящих данных — адреса изображений,
которые сохраняются как строки и отдаются браузеру после `safeUrl()`.
Проверка `A03: javascript: и data:text/html в imgs отклоняются` закрывает и
этот вектор: `http(s)` разрешены, `data:` — только `data:image/*`.

## Что осталось сделать на стороне инфраструктуры

Это нельзя закрыть кодом приложения — только настройкой площадки:

1. **HTTPS обязателен.** Без него куки уходят без `Secure`, а HSTS не включается.
   На Netlify/Cloudflare — автоматически; на VPS — certbot + nginx
   (`deploy/nginx.conf.example` уже содержит блок).
2. **HTTP Basic Auth поверх `/admin`** (nginx `auth_basic` или Netlify Password
   Protection) — второй фактор до загрузки страницы. Закомментированный блок
   есть в `deploy/nginx.conf.example`.
3. **Резервные копии `backend/data/` и `img/`** — это единственные
   невосстанавливаемые данные проекта.
4. **`DF_SECRET` в переменных окружения хостинга**, не в репозитории.
   При ротации секрета все сессии становятся недействительны (это ожидаемо).
5. **Обновление Node и зависимостей** на сервере; `npm audit --omit=dev` в CI.
