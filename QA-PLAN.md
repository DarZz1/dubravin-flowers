# QA-PLAN.md — план тестирования: адаптив, производительность, логика CMS

Три уровня проверки: **автоматизировано** (исполняется командой `npm test`),
**полуавтоматически** (скрипты и DevTools) и **вручную** (то, что нельзя
измерить без реального браузера и глаз).

Быстрый старт:

```bash
npm install          # jsdom (тесты) + busboy (сервер)
npm test             # 307 тестов: витрина, backend, QA
npm run server       # http://127.0.0.1:8090/  и  /admin
npm run backend:doctor
```

## 1. Адаптивная вёрстка (320 px и выше)

### 1.1 Автоматизировано — `tests/qa/responsive-performance.test.js`

| Проверка | Порог / ожидание |
|---|---|
| `meta viewport` на обеих страницах | `width=device-width, initial-scale=1` |
| Зум не заблокирован (WCAG 1.4.4) | нет `maximum-scale=1`, нет `user-scalable=no` |
| Брейкпоинты сетки | ≥5 уровней `.98`-соглашения, покрытие 320…1400+, порядок по убыванию |
| Фиксированные ширины | ни одного `width`/`min-width`/`flex-basis` больше 320 px (px, vw, rem) |
| Контейнеры резиновые | `max-width`, у `.wrap` нет жёсткой ширины |
| Типографика | `clamp()` или `rem/em/vw`; крупные начертания переопределены в адаптиве |
| Медиа | `img { max-width: 100% }`, у контейнеров есть `aspect-ratio`/высота, iframe отсутствуют |
| Тач-цели (WCAG 2.5.8 Minimum) | ни одной цели меньше **24 px** |
| Тач-цели (WCAG 2.5.5 Enhanced) | сводка по целям 24–43 px — печатается в лог теста |
| Горизонтальный скролл | `html,body{overflow-x:hidden}` заданы совместно; отрицательных margin больше 48 px нет |
| Шаблоны страниц | все 7 шаблонов роутера не содержат фиксированных ширин и жёстких таблиц |

**Текущий результат прогона.** Нарушений порога 24 px нет. Сводка по
рекомендации 44 px (это не дефект, а зона роста UX):

```
.theme-btn → 42px;  .btn-mini → 40/38/36px;  .hero-chip → 40/36px;  .chip → 40/38/36px;
.adm-bar-act .btn-mini → 38px
```

### 1.2 Ручная проверка в браузере — обязательный сценарий

Инструменты: Chrome DevTools → Toggle device toolbar (Ctrl+Shift+M),
Lighthouse (мобильный профиль), расширение «Responsive Viewer».

Ширины: **320** (iPhone SE), **360** (Android), **375** (iPhone 12/13),
**390**, **414**, **576**, **768** (iPad portrait), **992**, **1200**,
**1400**, **1920**.

| Шаг | Что сделать | Критерий приёмки |
|---|---|---|
| 1 | На каждой ширине открыть `#/`, `#/catalog`, `#/catalog/bouquets`, `#/product/1`, `#/delivery`, `#/contacts`, `#/privacy`, `#/terms`, `#/admin` | Горизонтального скролла нет (`document.documentElement.scrollWidth <= innerWidth`) |
| 2 | 320 px: hero, каталог, карточка товара, галерея, футер, меню-бургер | Текст не обрезан, кнопки в одну колонку или с переносом, ничего не наезжает |
| 3 | Бургер-меню на 320 px | Открывается, закрывается по крестику и по фону, пункты кликабельны, тема переключается |
| 4 | Галерея товара на 320 px | Миниатюры не вылезают, стрелки попадают под палец, счётчик «n / m» виден |
| 5 | Кастомный курсор на тач-устройстве | Не появляется вовсе (только при `pointer: fine`) |
| 6 | `/admin` на 320 px | Экран входа не обрезан, вкладки CMS прокручиваются, формы заполняются, таблица товаров не рвёт вёрстку |
| 7 | Поворот экрана (portrait ↔ landscape) на 375×667 | Вёрстка перестраивается без артефактов, меню не «залипает» |
| 8 | Зум 200 % (WCAG 1.4.10 Reflow) | Контент доступен без горизонтальной прокрутки |
| 9 | Клавиатура: Tab по витрине и по `/admin` | Фокус виден, порядок логичен, ловушек фокуса нет, Esc закрывает меню |
| 10 | Печать (Ctrl+P) главной | Разумный вид, нет чёрного фона на весь лист |

Скрипт для быстрой проверки переполнения во всех роутах (вставить в консоль):

```js
(async () => {
  const routes = ["#/", "#/catalog", "#/catalog/bouquets", "#/catalog/balls", "#/catalog/mono",
    "#/catalog/comp", "#/product/1", "#/delivery", "#/contacts", "#/privacy", "#/terms"];
  const bad = [];
  for (const r of routes) {
    location.hash = r;
    await new Promise(res => setTimeout(res, 700));
    const de = document.documentElement;
    if (de.scrollWidth > de.clientWidth + 1) bad.push(r + ": " + de.scrollWidth + ">" + de.clientWidth);
  }
  console.log(bad.length ? "ПЕРЕПОЛНЕНИЕ:\n" + bad.join("\n") : "Горизонтального скролла нет ✓");
})();
```

## 2. Производительность и Core Web Vitals

### 2.1 Автоматизировано (прокси-метрики)

| Метрика | Как измеряем | Порог | Факт на стенде |
|---|---|---|---|
| Вес собственного кода витрины | сумма HTML + CSS + JS | < 250 КБ | **147,6 КБ** |
| Число локальных ресурсов | `<link>` + `<script>` | ≤16 CSS, ≤16 JS | 13 CSS, 15 JS |
| Число сторонних подресурсов | только реально загружаемые | ≤4 | 3 (gsap, ScrollTrigger, Lenis) |
| gzip-эффект | `zlib.gzipSync(level 6)` | < 35 % | **32,9 %** (150,1 КБ → 49,4 КБ) |
| TTFB | медиана 7 запросов | < 200 мс | `/` 2 мс · `/api/content` 3 мс · `/admin/` 1 мс · CSS 1 мс · JS 1 мс |
| gzip по сети | `Accept-Encoding: gzip` | отдаётся | 9 828 Б → 3 418 Б (34,8 %) |
| Кэш статики | `Cache-Control` | CSS/JS ≥ 10 000 с | 604 800 с |
| Кэш HTML/API | `Cache-Control` | `no-cache`/`no-store` | соблюдено, у API есть ETag |
| Блокирующие шрифты | наличие `<link>` на CDN в HTML | 0 | 0 (загрузка через `fonts.js`) |
| Деградация CDN | fallback gsap/Lenis в коде | есть | есть + `try/catch` вокруг Lenis |
| Тема до первой отрисовки | `theme-init.js` в `<head>` до CSS | да | да (нет вспышки → меньше CLS) |
| Плейсхолдеры изображений | `loading="lazy"` или `data-imgfallback` | есть | есть + `aspect-ratio` у контейнеров |

### 2.2 Ручной замер настоящих Core Web Vitals

Автоматизировать LCP/CLS/INP без браузера нельзя — эти цифры снимаются только
в реальных условиях. Пороги Google: **LCP ≤ 2,5 с**, **CLS ≤ 0,1**, **INP ≤ 200 мс**.

**A. Полевые данные (то, что видит Google)**

1. PageSpeed Insights → введите прод-URL → вкладка «Реальные данные».
2. CrUX: `https://developer.chrome.com/docs/crux/dashboard` — динамика по 28 дням.
3. Search Console → «Основные интернет-показатели» → отчёты по мобильным и десктопным.

**B. Лабораторный замер (Lighthouse)**

```bash
npx lighthouse https://ваш-домен/ --only-categories=performance \
  --form-factor=mobile --screenEmulation.mobile \
  --throttling-method=simulate --output=html --output-path=./lh-mobile.html
```

Прогнать для: `/`, `#/catalog`, `#/product/1`, `/admin`.
Профили: мобильный с `Slow 4G` (основной) и десктопный (сравнение).

| Что смотреть в отчёте | Порог |
|---|---|
| Largest Contentful Paint | ≤ 2,5 с |
| Cumulative Layout Shift | ≤ 0,1 |
| Interaction to Next Paint | ≤ 200 мс |
| Total Blocking Time | ≤ 200 мс |
| First Contentful Paint | ≤ 1,8 с |
| Speed Index | ≤ 3,4 с |

**C. Ручная проверка CLS**

DevTools → Performance → запись → включить «Experience» → перезагрузить.
Искать блоки `Layout Shift` в таймлайне; у каждого смотреть `Cumulative Score`
и элемент-виновник. Отдельно проверить:

- подгрузку шрифтов (должна быть одна смена начертания, без прыжка строк);
- появление cookie-баннера (он должен резервировать место — `body.ck-on`
  сдвигает тост, это заложено в CSS);
- ленивую подгрузку фото в каталоге (контейнеры имеют фиксированные пропорции);
- бегущие строки (не должны менять высоту секции).

**D. Проверка INP в реальной работе**

DevTools → Performance → запись → активно кликать: бургер-меню, чипсы категорий
(там FLIP-анимация маркера), «Показать ещё» в каталоге, переходы по карточкам,
галерея товара, переключение темы, вкладки CMS. Смотреть долгие задачи (> 50 мс)
и задержку от клика до отрисовки.

**E. Нагрузочная проверка API (по желанию)**

```bash
npx autocannon -c 20 -d 30 http://127.0.0.1:8090/api/content
npx autocannon -c 10 -d 20 -m POST -H "Content-Type=application/json" \
  -b '{"login":"wrong","password":"wrong-password"}' http://127.0.0.1:8090/api/auth/login
```

Ожидание: p99 `GET /api/content` < 50 мс на локальном стенде; `POST /api/auth/login`
не падает, а уходит в `423`/`429` (это штатная защита, а не деградация).

## 3. Валидация логики CMS

### 3.1 Автоматизированные сквозные сценарии — `tests/qa/cms-scenarios.test.js`

Каждый сценарий = «админ сделал → проверили БД → проверили `data.json` →
отрендерили витрину боевым кодом в jsdom → проверили DOM».

| № | Сценарий | Ключевые проверки |
|---|---|---|
| 1 | Добавление товара | товар создан, цена 2450, `sale` определён автоматически, состав сохранён, `data.json` обновлён, карточка видна на главной и в каталоге «Букеты» после подгрузки (пагинация по 16) |
| 2 | Редактирование карточки | новое название/цена/описание/`hit`, непередаанные поля не выдумываются, `title` страницы обновлён, старых данных в DOM нет |
| 3 | **Замена фото** | 2 исходных файла на диске → после замены `removedOldFiles: 2`, на диске только новый, `1.png` и `2.jpg` физически удалены, старый URL отдаёт 404, при удалении товара папка исчезает |
| 4 | Удаление товара | товар исчез из каталога, медиа удалены (`removedFiles: 1`), прямая ссылка даёт 404-страницу |
| 5 | Подборки | новая подборка фильтрует каталог, при удалении у товаров очищается `cols`, сам товар не удаляется, подборки нет в навигации |
| 6 | Hero | изображение и заголовок применяются в разметке главной, `javascript:`-URL не проходит даже от авторизованного админа |
| 7 | **Совместное редактирование** | вторая запись со старой ревизией → `409 rev-conflict`, правка первого админа не затёрта, после перечитывания обе правки сосуществуют |
| 8 | Импорт и сброс | импорт каталога целиком применяется и виден посетителю, сброс восстанавливает 61 товар и 4 подборки |
| 9 | Доступы | редактор может править контент, смена пароля без текущего → 403, после смены все сессии редактора отозваны, сессия основного админа не пострадала |
| 10 | **Автономность витрины** | при недоступном API (`DF_SERVER_OK=false`) витрина полностью отрисовывается из `data.json` — режим статического хостинга не сломан |

## 5. Что намеренно НЕ автоматизировано

| Область | Почему | Чем закрываем |
|---|---|---|
| LCP / CLS / INP в реальных условиях | Нужен настоящий браузер и сеть | Lighthouse + PSI + CrUX (раздел 2.2) |
| Визуальная регрессия | Нет эталонных скриншотов проекта | Раздел 1.2 вручную; при желании — Playwright + `toHaveScreenshot()` |
| Кросс-браузерность (Safari, Firefox, старые Android) | В песочнице нет браузеров | Раздел 1.2 на реальных устройствах |
| Доступность полным прогоном (axe/WAVE) | Требует браузера | Пункты 9 раздела 1.2 + axe DevTools вручную |
| Нагрузочное тестирование продакшена | Зависит от железа площадки | `autocannon` (раздел 2.2 E) на стейджинге |
